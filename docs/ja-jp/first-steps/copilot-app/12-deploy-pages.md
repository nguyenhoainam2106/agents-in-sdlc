GitHub Pages で Space Quiz をデプロイして、公開できるようにします。Copilot はワークフローを準備し、デプロイを案内できますが、変更をレビューしてサイトが公開されたことを確認するのはユーザーの責任です。

このレッスンでは、次の操作を行います。

- Copilot に GitHub Pages のデプロイを構成するよう依頼します。
- ワークフローとプルリクエストをマージ前にレビューします。
- デプロイの進行を確認し、公開されたサイトを検証します。

## シナリオ

Space Quiz はすでに GitHub リポジトリにありますが、まだ簡単に試せる方法がありません。GitHub Pages で単一ファイルのサイトを公開すると、サーバーやランタイム依存関係を追加せずに、公開 URL からアクセスできるようになります。

## Copilot にデプロイの準備を依頼する

> [!WARNING]
> プルリクエストを作成すると、コードがコミットおよびプッシュされることがあります。このプロンプトを送る前に、承認設定と送信先のリポジトリを確認してください。**Approve all** を選択した場合、別途確認が求められるとは限りません。

`space-quiz` の Copilot アプリ セッションで、次のプロンプトを送信します。

```plaintext
このリポジトリの GitHub Pages デプロイを準備してください。必要に応じて Web サイトをビルドし、変更が既定のブランチに反映された後に GitHub Pages へデプロイする GitHub Actions ワークフローを作成してください。README がまだない場合は、アプリの説明とローカルでの実行方法を記載した README を追加してください。これらの変更を含むプルリクエストを作成し、そのリンクと必要な Pages の設定または権限を報告してください。マージ、自動マージの有効化、Pages 設定の変更、デプロイは行わないでください。停止してレビューを待ってください。
```

## ワークフローとプルリクエストをレビューする

1. リポジトリに README がまだない場合に限り、README が追加されていることを確認します。
2. ワークフローのビルドとデプロイの手順、トリガー、権限を含め、プルリクエストの変更をレビューします。
3. マージされていないプルリクエストではなく、既定のブランチからデプロイすることを確認します。
4. 必要な修正を依頼し、更新された diff をレビューします。マージを許可する前に、必須のプルリクエスト チェックがすべて成功するまで待ちます。

## マージとデプロイを許可する

> [!WARNING]
> 次のプロンプトを送信すると、レビュー済みのプルリクエストのマージ、リポジトリの Pages 設定の変更、サイトの公開をエージェントに許可します。レビューを完了し、リポジトリとプルリクエストを確認した後にのみ送信してください。承認設定によっては、追加の確認なしにこれらの操作が行われる場合があります。

`<PR_NUMBER>` をレビューしたプルリクエストの番号に置き換え、別のプロンプトとして送信します。

```plaintext
このリポジトリのプルリクエスト <PR_NUMBER> をレビューし、マージとデプロイを許可します。GitHub Actions を使って GitHub Pages を有効にし、必須チェックが成功した場合に限り、そのプルリクエストだけをマージして、デプロイが成功するまで監視してください。公開された Web サイトの最終 URL を報告してください。Pages の有効化またはマージの権限がない場合は、私が何を承認または実行する必要があるかを正確に説明してください。サイトが公開されるまでは、成功したと報告しないでください。
```

## デプロイを確認する

1. GitHub Actions のデプロイ実行が成功するまで確認します。
2. 報告された URL を開き、Space Quiz が表示されることを確認します。

エージェントが Pages を有効にしたりプルリクエストをマージしたりできない場合は、提示された具体的な手順に従ってください。デプロイが成功し、公開サイトが読み込まれるまで、タスクを完了したと見なさないでください。
